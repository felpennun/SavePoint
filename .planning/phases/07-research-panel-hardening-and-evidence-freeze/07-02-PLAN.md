<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Operador autenticado → Django Admin | Una identidad con cookies y formularios POST intenta gestionar datos del sistema. |
| Admin/servicios → modelos y auditoría | Acciones de usuario pueden cambiar datos personales, catálogo, jobs o estados de importación. |
| Repositorio/CI → despliegue | Código, lockfiles y configuración se convierten en una imagen pública. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-07-02-01 | Elevation of Privilege | `PlatformAdminSite` y ModelAdmin | critical | mitigate | Capability propia basada en `has_perm`, model permissions explícitos, CSRF y pruebas de separación de grupos. |
| T-07-02-02 | Tampering | `AuditEvent` | high | mitigate | Servicio allowlisted más trigger PostgreSQL que rechaza UPDATE/DELETE; operación sensible y test transaccional. |
| T-07-02-03 | Information Disclosure | admin, errores y logs | high | mitigate | Proyecciones readonly, redacción de errores, filtros de campos y tests de ausencia de secretos/PII innecesaria. |
| T-07-02-04 | Repudiation | anonymization/delete | high | mitigate | `operation_ref`, actor, resultado y timestamp en evento append-only antes de cada acción. |
| T-07-02-05 | Injection/DoS | forms, imports, headers | medium | mitigate | Validación de inputs, ORM parametrizado, CSRF, límites y throttle; pipeline ejecuta checks de seguridad. |
| T-07-02-SC | Tampering | dependencias y acciones CI | high | mitigate | No se cambia el conjunto de paquetes; CI exige lockfiles, checks de secretos y dependencias antes de integrar. |
</threat_model>
