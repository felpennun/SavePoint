# BLOCKING CONSTRAINTS — Read Before Anything Else

> These constraints were discovered through real failed Render deployments. A resuming agent must explain each failure and its prevention mechanism before changing deployment behavior.

- [ ] CONSTRAINT: Render `dockerCommand` is argv-oriented — never place nested `sh -c`, `&&`, or shell parameter expansion directly in the Blueprint command.
- [ ] CONSTRAINT: Production environment variables fail closed — preserve exact scheme/length validation and never weaken it to make deployment pass.
- [ ] CONSTRAINT: Provider secrets remain provider-local — never read, print, commit, or request them through chat.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Shell syntax in Render `dockerCommand` | Nested `sh -c` was treated as one command (exit 127); direct `&&` was passed as literal `manage.py` arguments (exit 2). | blocking | Keep `dockerCommand` exactly `sh /workspace/apps/api/render-start.sh`; keep sequencing and `${PORT:-10000}` inside the tested POSIX script. |
| Weak or malformed production secrets | Deployment correctly halted for a non-PostgreSQL `DATABASE_URL` and a `DJANGO_SECRET_KEY` shorter than 50 characters. | blocking | Enter only Neon `DATABASE_URL_UNPOOLED` as the value of Render `DATABASE_URL`; use a unique 50+ character secret key; retain fail-closed Django validation. |
| Declaring deployment success before public smoke | Provider preparation is complete but no public URL or green smoke exists. | blocking | Do not create `01-12-SUMMARY.md` or advance Plan 01-14 until Render `/health/`, Vercel proxy, commit identity and deployed Playwright smoke are verified. |
