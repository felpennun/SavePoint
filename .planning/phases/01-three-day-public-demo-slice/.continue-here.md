# BLOCKING CONSTRAINTS — Read Before Anything Else

> These constraints were discovered through real failures this session. A resuming agent must
> understand each one before touching deployment config again.

- [ ] CONSTRAINT: Never trust the long-lived local dev Postgres volume to prove a fresh-deploy fix works. It already contains rows from months of idempotent reruns, which silently masks bugs that only appear on a genuinely first-ever import (Neon's case). Always test deploy-path fixes against a brand-new container (`docker run` a fresh `postgres:18.6` with no named volume, or `docker compose down` + a fresh volume) before pushing.
- [ ] CONSTRAINT: `GameWork.id` is `models.UUIDField(default=uuid.uuid4)` — a fresh random value every independent first import assigns. Never hardcode or compare against a specific `GameWork.id` in any manifest, fixture, or test meant to run against more than one database. Use `canonical_slug` (deterministic) instead.
- [ ] CONSTRAINT: Render `dockerCommand` is argv-oriented — never place nested `sh -c`, `&&`, or shell parameter expansion directly in the Blueprint command (carried over from the previous pause; still true).
- [ ] CONSTRAINT: Next.js middleware's `matcher` runs before `next.config.ts` rewrites. Any path meant to be proxied straight through (like `/health/`) must be explicitly excluded from the locale-redirect matcher, or it gets 307-redirected as an "unrecognized locale segment" before the rewrite ever gets a chance to run.
- [ ] CONSTRAINT: Provider secrets remain provider-local — never read, print, commit, or request them through chat. (A real Neon connection string was accidentally printed once this session via `neon connection-string`; the user was told to rotate that password as a precaution. Use `scripts/check-secrets.ps1`'s canary patterns as the reference for what counts as secret-shaped.)

**Do not proceed until all boxes are checked.**
