## Decisions Made

- **Verify gate 1 ran against a local production build on :3100, not the shared :3000 container.** The `infra/compose.yaml` `web` service runs `next build && next start` serving a prebuilt `.next` from an anonymous volume — host edits to `apps/web/**` are bind-mounted but never rebuilt, so the container could not reflect the reflow CSS fixes. Building the worktree (`corepack pnpm --dir apps/web exec next build`) and `next start --port 3100` with `API_PROXY_TARGET=http://127.0.0.1:8000` gives a faithful production-mode target. `PLAYWRIGHT_BASE_URL` overriding is explicitly anticipated by the plan/prompt.
- **CSRF-origin shim.** Django's `CSRF_TRUSTED_ORIGINS` is `localhost:3000` / `127.0.0.1:3000`; a browser on `:3100` is rejected (403) on every unsafe `/api` call. The shim rewrites `Origin`/`Referer` to the canonical dev origin via `route.fetch({headers}) + route.fulfill` (plain `route.continue({headers})` does **not** override `Origin` in Playwright 1.62). Guarded to be a no-op when `PLAYWRIGHT_BASE_URL` is unset or contains `:3000`, so the orchestrator's post-merge re-run against the container is unaffected.
- **Recommendations shelves shown as onboarding.** `GET /api/recommendations/genre-taste/` returns `insufficient_history: true` for both `demo-visitor` and freshly registered accounts in the seeded dev DB (confirmed via the API). The recommendations evidence therefore captures the `algorithm_id` + `limitation` disclosure and the explicit "Aún no hay suficiente actividad" state; the test asserts *shelves OR onboarding* so a history-bearing environment also passes. Shelf grouping is unit-tested in 01.1-09.
- **Registration journey is rate-limit-tolerant.** The endpoint is 5/hour per IP (01.1-08). The journey test asserts `status ∈ {201, 429}`: 201 drives the full register → session → empty-collection → recommendations-nav path; 429 asserts the localized rate-limit UI-SPEC state. The 8 screenshots do not depend on this — `recommendations-*` come from the un-throttled demo-login path.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Mobile horizontal-overflow reflow failures in logged-out chrome + catalogue filter grid**
- **Found during:** Task 1 (first run of the existing `e2e/a11y.spec.ts` against the redesign build).
- **Issue:** The pre-existing "no page-level horizontal overflow at 320-375px" gate failed for homepage, login, catalogue and sources. Root causes: (a) `.sp-field` grid items default to `min-width: auto`, letting a `<select>` with long option labels / a number `<input>` force the mobile filter grid's `1fr 1fr` track past the viewport (catalogue → 585px doc width at 375px); (b) the header's fixed `gap-4 px-4` overran 375px once the redesigned right-end chrome (ThemeToggle text + login icon + menu button) was present.
- **Fix:** `min-width: 0` on `.sp-field` + `min-width: 0; max-width: 100%` on its input/select; header `gap-2 md:gap-4 px-3 md:px-4`. Desktop rendering unchanged (fields are already ≥180px there). Probe confirms `/es`, `/es/login`, `/es/catalogue`, `/es/sources` all reflow to exactly 375px.
- **Files modified:** `apps/web/app/globals.css`, `apps/web/components/AppShell.tsx` (not in `files_modified`).
- **Verification:** the 4 pre-existing overflow tests pass; new per-surface mobile reflow assertions pass.
- **Committed in:** `3c29976`.

**2. [Rule 1 - Bug] Two brittle assertions in the existing e2e suites**
- **Found during:** Task 1 (running `e2e/a11y.spec.ts` + `e2e/demo-journey.spec.ts` end to end).
- **Issue:** (a) `a11y.spec.ts` "one game detail page ... axe violations" injects axe immediately after `.click()` with no navigation wait — it intermittently scans the mid-navigation SSR document (no `<title>` → serious `document-title` violation). (b) `demo-journey.spec.ts` login tracer compares the detail `<h1>` to the card's title paragraph with `toHaveText` — but the detail `<h1>` deliberately appends `(year)` per 01.1-UI-SPEC Screen Contract 3, so it fails for any game with a release year.
- **Fix:** (a) `await page.waitForURL(/\/{locale}\/games\//)` + visible-`<h1>` before the scan. (b) `toHaveText` → `toContainText`.
- **Files modified:** `e2e/a11y.spec.ts`, `e2e/demo-journey.spec.ts` (both in `files_modified`).
- **Verification:** both tests pass across 3 consecutive full runs.
- **Committed in:** `3c29976`.
