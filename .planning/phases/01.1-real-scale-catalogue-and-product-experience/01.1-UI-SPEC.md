### Theming (light + dark)

Dark is the default. A light theme ships alongside it, selected by a persisted header toggle.

**Mechanism (executor implements in plan 01.1-06):**
- The existing dark token values stay in `:root` (unchanged). A new `[data-theme="light"]`
  selector block in `globals.css` overrides the **same** custom-property names with light
  values (below). Tailwind arbitrary values / `var(--color-*)` consume the runtime override
  automatically — no rebuild, no per-component change.
- `<html data-theme="…">` is written **server-side** in `app/[locale]/layout.tsx` from a
  `sp-theme` cookie (`"light"` | `"dark"`; absent → `"dark"`). The layout already reads
  `cookies()` for `sessionid`, so this adds no new pattern and produces **no flash** (the
  attribute is present in the first painted HTML).
- `ThemeToggle` (client) flips `document.documentElement.dataset.theme` immediately and writes
  the `sp-theme` cookie (`path=/`, `max-age` 1 year, `SameSite=Lax`, not `HttpOnly` — it is
  not a secret and the client must set it). Cookie chosen over `localStorage` specifically so
  SSR can read it; `localStorage` would force a client-only correction and a flash.
- `color-scheme` is set per theme: `:root { color-scheme: dark }`,
  `[data-theme="light"] { color-scheme: light }` (drives native form-control / scrollbar
  rendering).
- Respect `@media (prefers-color-scheme: light)` **only** as the default when no `sp-theme`
  cookie exists (optional nicety; dark remains the hard default if this is skipped).

**Light token values** (`[data-theme="light"]` overrides; contrast figures vs the light
`--color-surface-base #f4f4f7` unless noted):

```css
[data-theme="light"] {
  --color-surface-base: #f4f4f7;
  --color-surface-raised: #ffffff;
  --color-surface-overlay: #ececf1;
  --color-surface-border: #d9d9e0;

  --color-text-primary: #1b1b22;    /* on base ≈ 15.8:1 */
  --color-text-secondary: #4a4a57;  /* on base ≈  8.1:1 */
  --color-text-muted: #6c6c7a;      /* on base ≈  4.9:1 (AA body) */

  --color-accent: #6d5cd6;          /* on #ffffff ≈ 4.7:1 (AA body: links on card) */
  --color-accent-strong: #5a49c0;   /* hover */
  --color-accent-on: #ffffff;       /* text on accent fill ≈ 4.7:1 */

  --color-status-pending: #b7791f;
  --color-status-playing: #0e7490;
  --color-status-completed: #047857;
  --color-status-abandoned: #64748b;

  --color-danger: #c62828;          /* on #ffffff ≈ 5.9:1 */
  --color-success: #047857;
  --color-focus-ring: #8a5a00;      /* on #ffffff ≈ 4.9:1; ≥3:1 vs accent */

  --color-rating: #b0730f;          /* star fill on #ffffff ≈ 3.7:1 (UI component ≥3:1) */
  --color-score-weak: #6c6c7a;      /* = light text-muted */
  --color-score-fair: #b7791f;      /* on overlay #ececf1 ≈ 4.0:1 */
  --color-score-strong: #047857;    /* on overlay #ececf1 ≈ 4.9:1 */

```

Type-scale, spacing, and radii tokens are theme-independent (declared once). The 60/30/10
split, accent reserved-for list, and non-accent semantic assignments in `## Color` hold
**identically in both themes** — only the hex values differ.

| sm | 8px | Compact element spacing, card title-to-meta gap |
| ctl | 12px | Vertical padding inside compact controls / header (existing `py-3`) |
| md | 16px | Default gap — catalogue grid gap, card-to-card, form field spacing |

  cover render widths: 156px (catalogue/collection grid), 120px (recommendation shelf item),
  280px (detail-page hero, matches the existing `<img width={280} height={373}>`).

## Typography

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Body | 16px (`--text-body`) | 400 | 1.5 | Paragraph copy, list rows, value text, prose links |
| Label | 13px (`--text-meta`) | 600 | 1.4 | Card meta (year · platforms), genre chips, score pill, form `<label>`, filter-chip text, count/status line, table column headers |
| Heading | 20px (`--text-heading`) | 600 | 1.25 | `<h2>` section headings (filter results, recommendation shelf titles, detail-page subsections) |
| Display | 28px (`--text-display`) | 600 | 1.2 | `<h1>` page title (Catalogue, game title, Recommendations, Home wordmark-adjacent) |

Declared weights: **400 regular, 600 semibold** (exactly two). Existing `font-medium` (500)
usages in `GameCard.tsx` / `AppShell.tsx` migrate to 600 (titles, active nav) or 400 (meta).
Declared sizes: **13, 16, 20, 28** (four). No other font sizes.

Long-text rules:
- Card title: clamp to **2 lines** (`-webkit-line-clamp: 2`), full title remains the
  accessible link text and the `title=`/detail page shows it unclamped.
- Genre chip row: show up to **3** genres, then `+N` as a non-interactive chip.
- Prose (provenance, explainers, empty-state bodies) wraps freely; no clamping.
- Acceptance includes 30% text expansion and 400% zoom reflow (carried from Phase 1).

## Color

60 / 30 / 10 split. Hex values below are the **dark (default) theme** (already in
`globals.css`); the light-theme equivalents are in `## Design System › Theming`. The split,
the accent reserved-for list, and every non-accent semantic assignment are **the same in both
themes** — only the values change.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface-base` `#0d0d12` | Page background, main content column, grid gutters |
| Secondary (30%) | `--color-surface-raised` `#17171f` (cards, header/nav, filter bar) + `--color-surface-overlay` `#1f1f2b` (dropdown menus, mobile filter disclosure, hover/selected chip, account switcher panel) | Card surfaces, chrome, elevated surfaces |
| Accent (10%) | `--color-accent` `#8b7cf6` / `--color-accent-strong` `#a394ff` (hover) with `--color-accent-on` `#16121f` for text on accent fill | See reserved-for list below |
| Destructive | `--color-danger` `#f87171` | "Clear rating"; "Remove copy"; any future account delete/anonymise (PRIV-02, not this phase) |

**Accent reserved for — explicit list (never "all interactive elements"):**
1. Primary action button **fill** — one per screen: "Add to collection" / "Update status"
   (game detail), "Apply filters" (catalogue), "Create simulated account" (register), "Log
   in" submit (login).
2. Text links inside prose / body copy (provenance source link, empty-state "Browse
   catalogue" link, "Clear all filters" link).
3. Active navigation item — `aria-current="page"` underline/marker in the header.
4. Current page marker in pagination.
5. Focused/selected state outline on a filter `<select>`/chip (in addition to the global
   `--color-focus-ring` which stays gold).

**Accent must NOT be used for:** card borders, cover frames, the IGDB score pill (uses the
`--color-score-*` ramp), backlog status pills (use `--color-status-*`), personal rating stars
(use `--color-rating`), recommendation "why" text (uses `--color-text-secondary`), or generic
hover backgrounds (use `--color-surface-overlay`).

Non-accent semantic colors (existing, reused): `--color-status-pending/playing/completed/
abandoned` for the backlog status pill; `--color-success` for the "saved" confirmation line;
`--color-rating` (new) for stars; `--color-score-*` (new) for the critic-score pill.

Contrast: every new pairing must clear WCAG 2.2 AA (4.5:1 body text, 3:1 large text / UI
components) against its background **in both themes**, verified with the axe-core pass
(QUAL-03/QUAL-05). Known-good (dark): `--color-score-strong #34d399` on
`--color-surface-overlay #1f1f2b` ≈ 7.3:1; `--color-rating #f5b544` on the same ≈ 8.9:1;
`--color-score-fair #f0b429` ≈ 8.4:1. Light-theme figures are listed inline in
`## Design System › Theming`.

## Screen Contracts

### Navbar (all pages) — `components/AppShell.tsx`

The header is `--color-surface-raised` with the existing border token. Left→right:

1. **Brand** "SavePoint" — link to `/{locale}`.
2. **Primary nav** — Home, Catalogue, Sources (always); Collection + Recommendations
   (authenticated only). `aria-current="page"` on the active item (accent underline).
3. **`ThemeToggle`** — visible to every visitor (see component contract).
4. **Right-end account slot** — exactly one of:
   - **Logged out:** a **person-icon button** (inline SVG, `aria-label` = `nav.loginAria`
     "Log in" / "Iniciar sesión"; the label may also render as visible text beside the icon on
     ≥ md). It is the **rightmost** navbar item. It is a plain `<Link>` to the dedicated full
     page `/{locale}/login` — **not** a dropdown, **not** a modal. 44px target, keyboard-
     operable, visible focus ring.
   - **Logged in:** the `AccountSwitcher` trigger (avatar/initial + "Simulated account:
     {alias}" + chevron) occupies that same rightmost slot instead. Opens the account menu
     (see Screen Contract 5a). The person-icon login button is not rendered.
5. **Mobile (< md):** primary nav collapses into the existing `MobileMenu` disclosure; the
   `ThemeToggle` and the right-end account slot (person-icon **or** `AccountSwitcher`) stay
   visible in the header bar, not inside the disclosure.
