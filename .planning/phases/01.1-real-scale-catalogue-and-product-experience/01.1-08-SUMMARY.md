# Phase 01.1 Plan 08: Controlled Functional Registration Summary

**csrf_protect AllowAny `RegisterView` — Django `validate_password`, `transaction.atomic` `create_user`, session login, and a scoped 5/hour per-IP anonymous throttle — completing AUTH-02 / D-02 via D-08's middle path without opening AUTH-03.**

## Accomplishments

- `RegisterView` mounted at `POST /api/accounts/register/`: `csrf_protect` + `AllowAny`, mirrors `LoginView`'s CSRF re-application for an anonymous endpoint.
- Account creation path: case-insensitive duplicate rejection (409), Django `AUTH_PASSWORD_VALIDATORS` via `validate_password` (400 on weak), `transaction.atomic` `create_user` with an `IntegrityError` → 409 race fallback, then `login(request, user)` (session-key rotation for free).
- New account is **active and non-simulated** — no `DemoAccountIdentity` row is created here; that marker stays seed-only (`bootstrap_demo_accounts`, 01.1-04).
- Scoped anonymous DoS mitigation (threat T-01.1-07): `ScopedRateThrottle` scope `"registration"` at `5/hour` per client IP, declared through a **rates-only** `REST_FRAMEWORK` block so `DEFAULT_THROTTLE_CLASSES` stays empty and no other view is affected. No new dependency — `ScopedRateThrottle` ships with `djangorestframework==3.18.0`.
- Allowlisted response body `{"detail": "ok", "next": "/catalogue"}` at `201`, matching `LoginView`'s shape.
- Frontend already satisfied by 01.1-06: `register/page.tsx` performs the CSRF bootstrap, POSTs `{username, password}`, maps `409/400/429` to the localized `t.errorDuplicate` / `t.errorWeakPassword` / `t.errorRateLimited` rows, and on `response.ok` calls `router.push(\`/${locale}/catalogue\`)`.
- No email verification, no social auth, no "unrestricted"/"production account"/"AUTH-03" language anywhere — guarded by an automated source scan test.

## Decisions Made

- **Throttle scope/rate: `registration` @ `5/hour` per IP.** `ScopedRateThrottle` over `AnonRateThrottle` so the ceiling is dedicated to this endpoint and does not consume/according-to a shared `anon` bucket. 5/hour is deliberately tight for a controlled academic demo while still letting a genuine visitor (and a mistaken retry or two) through.
- **Case-insensitive duplicate check** (`username__iexact`) so `Alice` and `alice` cannot co-exist and confuse the demo; `IntegrityError` fallback covers the create race. Both surface as `409`.
- **`lib/api.ts` left untouched.** The plan's file list named it, but that module is explicitly documented "Never imported from a Client Component" and uses server-to-server absolute URLs; the sibling `login/page.tsx` (the pattern the task said to mirror) also issues its auth POST inline. `register/page.tsx` from 01.1-06 already implements the full client contract, so no frontend change was required or appropriate.
