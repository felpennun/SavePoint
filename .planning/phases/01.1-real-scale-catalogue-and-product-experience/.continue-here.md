## KNOWN ISSUE — B (catalogue load) blocked by a real coexistence bug (found 2026-09-05 ~21:20 UTC)

Running `import_igdb_catalogue` against `savepoint_test` (the real dev DB, already holding the 150-game Wikidata corpus) **aborts immediately**:

```
CommandError: IGDB import aborted: duplicate key value violates unique constraint
"catalogue_platform_slug_key"  DETAIL: Key (slug)=(web-browser) already exists.
```

The IGDB importer's Platform normalization keys on IGDB platform identity / a SourceRecord, NOT on `Platform.slug`, so it tries to INSERT a platform whose `slug` already exists from the Wikidata import instead of reusing it. Never fired on the empty fresh-DB acceptance run (no pre-existing platforms) — this is exactly the `source="igdb"` ↔ `source="wikidata"` coexistence risk decision B was meant to surface.

**Fix needed (in `apps/api`, needs a test):** platform upsert must `get_or_create` / reconcile on `slug` (link the IGDB `SourceRecord` to the existing Platform row) rather than blind-insert — most platforms *were* reused fine (Wikidata+IGDB now share `atari-2600`, `dos`, etc.), so the bug is a specific path (likely an in-batch `bulk_create` collision on `web-browser`). Add a Wikidata-then-IGDB coexistence test to `test_igdb_import.py`.

**Partial state left behind:** the aborted run committed **~500 IGDB games** + platforms + an `IgdbImportRun` row into `savepoint_test` before hitting `web-browser`. `catalogue_gamework` = 650 (150 Wikidata + 500 IGDB). Before re-running B: either trust the resumable design to converge them, or (safer, since the fix changes platform linking) delete the `source="igdb"` `SourceRecord`s + their orphaned `GameWork`/`GameRelease` rows + the `IgdbImportRun` row for a clean proof. Migration `0003` is applied.
