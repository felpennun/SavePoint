# Phase 01.1 Plan 05: Genre-taste recommendation service + authenticated API Summary

**Deterministic, owner-scoped `rank_genre_taste_v1` heuristic (status/rating-weighted genre frequency over the user's own library, canonical_slug tie-break, `input_snapshot_sha256` fingerprint) exposed at `GET /api/recommendations/genre-taste/` behind `IsAuthenticated`, with ADR-007 bounding it away from Phase 6's recommender.**

## Accomplishments
- `rank_genre_taste_v1(user, limit)` — a stateless request-time service that weights the user's genres by their own `completed/playing/pending` + rating activity, then ranks unseen, non-DLC catalogue works by summed genre-overlap weight. Deterministic `canonical_slug` tie-break, per-item `matched_genres` explanation evidence, `input_snapshot_sha256` reproducibility fingerprint, explicit `limitation` string, and a distinct `insufficient_history` shape that never falls back to the public popularity baseline (D-09).
- New `apps/api/recommendations/` Django app (registered in `INSTALLED_APPS`, no models, no migrations) with `RecommendationsView` (`IsAuthenticated`) mounted at `/api/recommendations/`, `GET /api/recommendations/genre-taste/` returning the allowlisted DTO.
- Bounded candidate query: driven by the `GameWork.genres` M2M through table filtered on the auto-indexed `genre_id` and SQL `LIMIT`-capped, so the genre-overlap scan is never unbounded over the 312k-row catalogue (threat T-01.1-11).
- `limit` bound: clamped to `[1, 50]`, default `20`; non-integer `limit` -> `400`, out-of-range integer -> clamped.
- `docs/adr/ADR-007-genre-taste-heuristic.md` — records the exact weights, tie-break, exclusion rules, the `input_snapshot_sha256` mechanism, and the explicit "product feature, not the thesis's algorithmic contribution" boundary; cross-references `library/popularity.py` (REC-02) as the sibling non-personalized baseline.
- 21 new tests (`test_genre_heuristic.py`) green; full `pytest apps/api` regression 202 passed; `makemigrations --check` clean.

## Decisions Made
- **Genre weights:** reused `library/popularity.py`'s `_STATUS_WEIGHTS` verbatim (`completed 3.0, playing 2.0, pending 1.0, abandoned 0.0`) and the same `rating_half_steps / 10` rating term, so the personal heuristic and the public baseline are calibrated identically. A genre's taste weight is the sum of those per-entry activity weights across every user library entry whose work carries that genre.
- **`limit` bound:** `[1, 50]`, default `20`. Endpoint rejects a non-integer `limit` with `400`; clamps out-of-range integers. The service also clamps, so a direct (non-HTTP) caller is bounded too.
- **No new index / migration:** the M2M through table's auto-created `genre_id` index plus a SQL `LIMIT` bound the candidate scan; `canonical_slug`'s unique index serves the tie-break. The `recommendations` app has no models.
- **`tests/__init__.py` added:** matches the `accounts`/`catalogue` test-package layout (not explicitly listed in the plan's files, structural scaffolding only).
