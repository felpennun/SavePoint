# Phase 01.1 Plan 06: Real-Scale Catalogue and Product Experience — UI redesign Summary

**Implemented the checker-verified 01.1-UI-SPEC across every apps/web surface: a first-party light/dark CSS-variable token system with a persisted no-flash ThemeToggle, redesigned GameCard/navbar/catalogue/detail/collection/home/login, two new surfaces (genre recommendations + registration), and the Cristal brand identity — build and vitest green, no new dependencies.**

## Accomplishments

- **Token system (globals.css):** new `--color-rating`, IGDB score ramp, 4-size type scale, 4→64 spacing scale added to `@theme`; a full `:root[data-theme="light"]` override set (same names, light values); `color-scheme` per theme; a `prefers-reduced-motion` guard; and a `.sp-*` component utility layer (card, cover, score/status pill, chip, filter field/bar, shelf, buttons, page shell). Legacy `font-medium` (500) usages removed with the GameCard/AppShell rewrites.
- **Theming:** `[locale]/layout.tsx` sets `<html data-theme>` server-side from an `sp-theme` cookie (no flash); `ThemeToggle` (visible to every visitor, icon + text label, `aria-pressed`, 44px) flips `document.documentElement.dataset.theme` and writes the cookie.
- **Components:** `ScorePill` (tiered, never accent, null→nothing), `StatusPill`, `StarRating` (role=img + aria-label), `CoverImage` (client `<img>`, `onError`→first-party placeholder per ADR-006), `FilterBar` + `FilterChip`, `RecommendationShelf`, `AccountSwitcher` (focus-trapped menu reusing the MobileMenu pattern), `LoginIconButton`, `DemoAccountBanner`, `BrandLockup` (inlined mono lockup, `currentColor`, violet inner-diamond accent).
- **Navbar:** brand lockup, primary nav (+ Recommendations, auth-only), ThemeToggle, right-end slot = LoginIconButton (logged out) / AccountSwitcher (logged in), DemoAccountBanner under the header on authenticated pages.
- **Catalogue:** server-rendered `FilterBar` (platform/genre/year-from/year-to/min-rating + 6 sort keys), GET-only URL-shareable, allowlist validation (`apps/web/lib/catalogue-filters.ts`), count line, active-filter chips, `<details>` collapse on mobile, param-preserving pagination, filtered vs text-search empty states.
- **Game detail:** two-column cover hero + title/year, ScorePill, genre chips, platform list, localized release date, LibraryControls in a surface card, provenance now `source · source_id · licence · retrieved_at` + static "Data from IGDB.com" + link to `/sources`.
- **New /recommendations (REC-10):** auth-gated like `/collection`; genre-grouped horizontal shelves (cap 4), per-shelf explainer, insufficient-history state visually distinct from `RecommendationStrip`.
- **New /register:** centered card, username + password + confirm, inline mismatch guard, `aria-describedby`-linked `role="alert"` errors, pending state, link to login; submit maps the four contracted error rows by HTTP status so Plan 04/08 only wires the backend.
- **Collection + home + login + sources:** redesigned onto the token system (collection: status filter + sort + status-summary `StatusPill`s + per-card status/stars/copies + empty states; home: logged-out CTA row + sample grid / signed-in greeting + continue row + recommendations CTA; login: sp-surface card + register link).
- **Brand:** `apps/web/app/icon.svg` favicon; `apps/web/public/brand/banner-og.svg` (CRISTAL iteration label removed) wired via `metadata.openGraph`.
- **next.config.ts:** `images.remotePatterns` = `images.igdb.com` only (ADR-006 / threat T-01.1-12).
- **i18n:** ~90 new EN/ES parallel keys; `Dictionary` interface extended in step; `apps/web/tests/i18n.test.ts` green.

## Decisions Made

- **`catalogue.resultCount` left at "results"/"resultados".** `apps/web/tests/i18n.test.ts` hard-codes its exact values; the UI-SPEC's "reuse it, revalued to 'games'" note would break that test. Added `catalogue.gamesCount` ("{n} games") for the count line instead.
- **GameCard cover is `<img>` via `CoverImage`,** per the UI-SPEC First-Party Component Contracts ("tiny client wrapper around `<img>`"), not `next/image` (mentioned in the task brief). `images.remotePatterns` for `images.igdb.com` was still added per the success criterion and is ready if `next/image` is adopted later.
- **Light theme override in `:root[data-theme="light"]`** (not a bare `[data-theme]`) for specificity safety over Tailwind's `@theme` → `:root` emission.
- **Data owned by later plans is modelled as optional fields + null-tolerant helpers.** `total_rating`/`genres` on `GameCard`/`GameDetail`, cover/year on `MyLibraryItem`, `fetchRecommendations`, `fetchAccountMe` — all render placeholders / empty states today and light up when Plan 03/04/05 ship the values.
