<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente autenticado -> `ContentRecsView` (`algorithm_id`, `limit`) | entrada no confiable; `algorithm_id` no debe seleccionar un code path arbitrario |
| `CorpusRatingSnapshot` (congelado) -> término de rating | el modelo lee el snapshot, nunca el valor vivo |
| perfil de otro usuario | el endpoint solo sirve `request.user` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11-01 | Tampering / RCE-adjacent | `algorithm_id` usado para seleccionar un code path | high | mitigate | comprobación de pertenencia a `ALGORITHM_REGISTRY` únicamente; nunca `importlib` / `getattr` sobre el valor; 400 acotado si desconocido |
| T-02-11-02 | Information Disclosure | `ContentRecsView` filtrando el gusto de otro usuario | high | mitigate | `IsAuthenticated` + `request.user`-only, sin parámetro de usuario objetivo; proyección allowlist-echo (ADR-007 §7) |
| T-02-11-03 | Tampering | modelo leyendo `GameWork.total_rating` en vez del snapshot | high | mitigate | `combine.rating_term` lee `CorpusRatingSnapshot` de la `corpus_version` activa; test que falla si lee el valor vivo (DATA-06) |
| T-02-11-04 | Hallucination / integridad de evidencia | explicación con prosa generada | medium | mitigate | `explain` produce solo una tabla de contribución + términos numéricos de features persistidas; sin LLM (AGENT-04) |
| T-02-11-05 | Denial of Service | ranking sobre ~150k candidatos por request | medium | mitigate | vectores dispersos + `WorkFeatureVector` cacheado; `limit` acotado a `[1,50]`; el endpoint reutiliza el throttling de DRF del proyecto |
</threat_model>
